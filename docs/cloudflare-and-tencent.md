# 线上发货与后续迁移

## Cloudflare 上线方式

- 域名：`https://lingmianlab.top`；后台：`https://lingmianlab.top/admin`。
- Worker 名称 `worker`，数据库 `other-side-db`。保留已有数据，初始化脚本不会删表。
- 在 Cloudflare 中设置 `ADMIN_KEY` Secret，绝不能写入 Git 或前端源码。
- 正式构建默认 `ALLOW_PUBLIC_EXPLORE=false`：公开首页不能自动发免费测试。
- 本地 `.dev.vars` 可设 `ALLOW_PUBLIC_EXPLORE=true`，仅用于自己调试。
- 后台每批生成 1—100 条，可反复生成，无程序设置的累计条数上限。
- 链接为随机 256 位 token，数据库主键约束确保不重复。若极小概率碰撞，本批报错且不会返回重复链接。
- 一条链接对应一份答题进度和固定报告，不绑定某个人的身份或设备；持有链接的人可以访问，所以不要公开客户链接。
- 24 小时从第一次开始答题计算，生成时不会开始倒计时；提交后报告保持可访问。
- 后台列表展示最近 500 条，超过 500 条不会删除老链接。CSV 是发货清单，不是数据库备份。
- Cloudflare 的请求、读写、存储额度仍适用；不能承诺无限流量或无限免费存储。

## 数据备份

授权 Wrangler 后，运行 `node scripts/backup-cloudflare.mjs`。
完整业务表 SQL 会写到被 Git 忽略的 `.sites-runtime/backups/`，包含链接、状态、时间、答案、题库版本和已生成报告。
这些文件包含客户资料与访问凭证，应私人保存，并另存到受保护的位置；不要放入网站静态目录或 Git。

## 腾讯云迁移步骤

迁移不需要重写题库或页面，但目前后端使用 `cloudflare:workers` 和 D1 绑定，不能只把 dist 复制到 Ubuntu 就运行。

1. 在腾讯云准备 Node 服务与 SQLite；把 D1 的 prepare/bind/first/all/run/batch 接口换成服务器上的 SQLite 适配层，保留原有 API 地址、鉴权和并发提交约束。
2. 用测试数据库演练 SQL 导入；校验 token、题库版本、时间、答案及报告完整性。保留 3.0、3.1、3.2 题库，避免旧报告引用新题目。
3. 用临时测试入口验证管理登录、发货、24 小时限制、恢复进度、并发提交、旧报告与停用功能。
4. 切换前短暂停止旧端写入，导出最终数据并导入新库；核对记录数及抽样报告。不能让两个独立数据库同时接受提交。
5. 将同一域名解析到腾讯云并配置 HTTPS；如果保留 Cloudflare 普通代理，跨境链路仍可能慢，国内访问方案需另行配置。
6. 旧链接的域名和 `?t=` 不变，数据库保留原 token，所以客户无需重新领链接。旧的答题截止时间也不能因迁移重置。
7. 保留切换前备份。若需回滚，应先处理新端产生的写入，再切回旧端，不能直接回滚丢失新进度。

前提是国内服务已满足备案及实际业务要求。此文档是迁移方案，腾讯云运行适配与迁移演练尚未完成。
